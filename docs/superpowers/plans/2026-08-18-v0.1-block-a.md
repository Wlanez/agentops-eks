# v0.1 Block A — AWS Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first reproducible AWS foundation for `agentops-eks`: protected Terraform state, a two-AZ VPC, Amazon EKS with a managed node group, and an immutable ECR repository.

**Architecture:** Use explicit HashiCorp AWS provider resources rather than a large convenience module so the repository exposes the platform primitives we intend to teach. The dev profile uses two Availability Zones and a single NAT gateway as an intentional cost-aware lab compromise. EKS uses API authentication mode, managed EC2 nodes in private subnets, and managed core add-ons.

**Tech Stack:** Terraform >= 1.10, HashiCorp AWS provider 6.x, Amazon VPC, S3, IAM, EKS, EC2 managed node groups, ECR.

**Spec:** `docs/milestones/v0.1-foundation.md` and `docs/instructor/first-principles.md`

## Global Constraints

- Follow **AI Platform from First Principles**: explain the system before automation; Block A contains no AI.
- Default AWS region: `us-west-2`, configurable.
- Default EKS Kubernetes version: `1.36`, configurable and currently in EKS standard support.
- Use two Availability Zones.
- Use public and private subnet separation.
- Use one NAT gateway in the lab profile; document the availability/cost tradeoff.
- Managed EKS workers run in private subnets.
- No inbound SSH path is required for cluster administration.
- Remote Terraform state uses S3 versioning, encryption, public-access blocking and native S3 lock files (`use_lockfile = true`).
- ECR image tags are immutable and scan-on-push is enabled.
- Do not add FastAPI, Helm, OpenTelemetry, AI agents or GitHub deployment workflows in Block A.
